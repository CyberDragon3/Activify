## Project Overview

Activify is a **Chrome MV3 side-panel extension** that scrapes school platforms on demand (Google Classroom, Canvas, Schoology), organizes assignments, and builds a daily study plan using **Groq AI**. A companion **Expo React Native mobile app** reads synced data. Both share the same Supabase project for auth and cloud storage. All extension code is plain JavaScript — no TypeScript, no React in the extension.

## Architecture

### Extension Data Flow

Content scripts scrape assignment DOM on school platforms and send `ACTIVIFY_AI_DATA_COLLECTED` messages to the service worker. The service worker calls `mergeAssignments()` from the shared storage module, which writes to `chrome.storage.local` and then fire-and-forgets a sync to Supabase. The side panel listens for `ACTIVIFY_REFRESH` messages and re-renders.

Scans are triggered two ways:
- **Automatically** — via a `chrome.alarms` alarm every 30 minutes (service worker injects/re-invokes content scripts on open tabs)
- **Manually** — via the scan button in the side panel

### Shared Storage Module (`shared/storage.js`)

This is the **single source of truth for all data access**. Other extension files import from `../shared/storage.js` directly. The `npm run build` step bundles it into `storage.bundle.js` (which imports `./supabase-lib.js`) — keep both in sync by rebuilding after any edit to `storage.js`.

Storage is dual-layer:
- **`chrome.storage.local`** — primary read/write cache; fast and available offline
- **Supabase** — cloud sync; writes are fire-and-forget and fail silently if unauthenticated

The Supabase client uses a custom `ChromeStorageAdapter` so session tokens persist in `chrome.storage.local` (not `localStorage`, which is unavailable in service workers).

### Side Panel Auth Gate

`manifest.json` sets `sidepanel/auth.html` as the default side panel path. On load, `auth.js` checks for an existing session and redirects to `index.html` if found. `panel.js` also checks for a user on init and redirects back to `auth.html` if unauthenticated.

### AI Assistant (`sidepanel/ai.js`)

- Uses the **Groq API**, model `llama-3.3-70b-versatile`
- The Groq API key is stored in `chrome.storage.local` under the key `groqApiKey`, entered by the user in Settings
- When the AI suggests a schedule, it emits a ` ```tasks ` JSON block
- `applyTasksFromResponse()` atomically clears all tasks with IDs prefixed `ai_` and replaces them with new suggestions
- Manual/imported tasks are never affected — their IDs use a hash-based format

### Content Scripts

There is a single content script: `content/ai_scraper.js`. It runs on all supported school platforms and sends `ACTIVIFY_AI_DATA_COLLECTED` messages to the service worker. It never calls Supabase or Groq directly — all external calls go through the service worker.

### Mobile App (`mobile/App.js`)

The entire mobile app is a single file. It is **read-only** — tasks and assignments are created via the extension and synced to Supabase; the mobile app only reads them. Auth uses email/password (not Google OAuth). Push notifications are scheduled locally via `expo-notifications` based on task start times.

### Key Data Conventions

- **Assignment IDs** — deterministic hashes of `source:course:title`, generated independently in each content script and in `storage.js`'s `makeId()`
- **AI task IDs** — prefixed `ai_` so they can be bulk-cleared without affecting user-created tasks
- **Dates** — stored as `YYYY-MM-DD` strings throughout
- **Times** — stored as `HH:MM` (24-hour) strings
- **Module format** — service worker uses ES modules; content scripts use IIFEs

### Supabase Schema

Two primary tables, both with `user_id` for row-level security:
- `tasks` — `id`, `user_id`, `title`, `date`, `start_time`, `duration_mins`, `completed`, `category`, `color`, `assignment_id`
- `assignments` — `id`, `user_id`, `source`, `course`, `title`, `due_date`, `due_time`, `type`, `url`, `completed`, `scanned_at`

## Declared Permissions (manifest.json)

- **Permissions:** `sidePanel`, `storage`, `tabs`
- **Host permissions:** `https://*.supabase.co/*`, `https://classroom.google.com/*`, `https://*.instructure.com/*`, `https://*.schoology.com/*`, `https://api.groq.com/*`

Adding any new `chrome.*` API or new external domain requires adding it to `manifest.json` first. Ask before doing so.
